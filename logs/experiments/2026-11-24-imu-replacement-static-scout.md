## 1. 사전등재 (실행 전)

- **질문 / 가설**: 교체한 MPU6050을 정지 상태로 지지하여 탐색 1회를 수집할 때 센서 설정·로그 무결성·전원 기록 조건을 충족하는지, 자이로 원시 출력이 어떻게 나타나는지 확인함. 원인 확정·보정값 결정·균형 성능 평가로 취급하지 않음.
- **센서 식별 이력**: 학생이 11/20 r02 이후 MPU6050 자체를 다른 MPU6050으로 교체했고 축 방향은 동일하며 Pi에서 인식을 확인했다고 알림. 인식 명령·출력과 새 센서의 개별 식별자는 제공받지 않음. 이번 파일명의 `replacement`로 교체 전 로그와 구분하며, WHO_AM_I를 센서 개체의 고유 번호로 해석하지 않음.
- **비교 대상**: 새 센서 한 조건의 탐색 n = 1로 계획함. 기존 `imu-first`·11/20 r01·r02는 교체 전 센서의 전체 VOID 기록으로 보존함. 센서·전원·지지 조건이 달라 기존 수치와의 차이를 센서 교체 효과로 판정하지 않음. 유효한 baseline 성능 비교를 수행하지 않음.
- **정합 축**: 외란을 가하지 않고 수집 시작부터 끝까지 같은 자세·본체·박스·지지면 상태를 유지함. 다른 자세·다른 센서의 대조 실행이나 확증 반복은 이번 계획에 포함하지 않음.
- **공통 조건**: 코드의 `SAMPLE_RATE_HZ` 한 변수에 따른 호스트 목표 30 Hz, 수집 창 30초, 목표 900샘플을 사용함. 첫 샘플부터 마지막 샘플까지 이상적 시간차는 899/30초임. 센서 내부 출력률 100 Hz, DLPF_CFG 5, SMPLRT_DIV 9, 가속도 ±2 g, 자이로 ±250 deg/s를 사용함. 기존 코드·센서 설정·변환·안전 한계를 변경하지 않음.
- **실행 가정**: 수집기의 기존 기본값인 I2C bus 1·주소 `0x68`을 사용함. 이는 새 센서 인식 출력으로 독립 확인한 값이 아님. 학생이 확인한 bus·주소가 이 값과 다르면 실행하지 않고 보고함.
- **실제 적용값**: JSON의 시작·종료 설정과 WHO_AM_I를 각각 11개, 총 22개 필드로 대조함. 호스트 주기는 CSV 단조 시각으로 검사함. 기존 수집기가 시작 시 센서를 초기화하고 설정을 기록하므로 단순 I2C 인식 보고와 실제 설정 검증을 구별함.
- **전원 준비 사실**: 학생이 배터리→모터 드라이버→모터 연결과 컨버터를 통한 Pi 전원 공급을 알림. 현재 배터리→모터 드라이버 입력선을 분리했다고 확인함. 에이전트가 회로·잔류 전원·다른 공급 경로를 독립 측정한 것으로 표현하지 않음.
- **실행 전 구동 조건**: 학생이 위 입력선 분리 상태가 유지되고 드라이버에 다른 모터 구동 전원 공급 경로가 없으며 별도 모터 제어 프로그램이 실행되지 않음을 확인한 뒤 장치 옆에서 수집함. Pi·센서 전원은 유지함. 실제 전원 분리·비구동 확인과 수집기의 `motor_interface: none`을 구별함. 에이전트는 센서·모터 실물 명령을 실행하지 않음.
- **전압 조건**: 학생이 수집 직전에 배터리 전체 DC 전압 [V]을 다시 실측하고 `--vbat`로 입력함. 이전 런의 전압을 재사용하거나 추정하지 않음. CSV의 반복 전압값은 수동 사전 측정값이며 실시간·셀별 전압이나 배터리 잔량을 측정한 것으로 해석하지 않음. 전체 전압만으로 배터리 또는 회로의 안전 적합성을 판정하지 않음.
- **장착·자세 조건**: 학생이 옆의 박스로 본체를 고정했으며 교체 후 센서 축 방향은 같다고 확인함. 정확한 몸체 축 대응·부호·기울기 각도·직립 오프셋은 미확정으로 둠. 실행 전에 본체·박스·지지면의 미끄러짐과 바퀴 굴러감을 막고 수집 중 자세가 유지되는지 관찰함. 실제 앞/뒤/옆 기울임과 흔들림 유무를 실행 후 제공함. 몸체 축 변환·직립 영점 보정은 적용하지 않음.
- **측정 필드**: 센서 축 원시값 7개와 물리량 7개·온도·시각·tick·오류·수동 전압을 보존함. 몸체 기울기·몸체 각속도·좌우 바퀴 속도·좌우 모터 출력은 미측정 빈 값으로 유지함. 빈 값을 0으로 해석하거나 교체 전 센서의 평균을 새 센서 bias로 빼지 않음.
- **단계**: 승인 범위의 사전등재 파일 1개를 commit·origin/main push하고 원격 반영을 확인함 → 학생이 Pi에서 pull하고 전원·고정·프로그램·bus/주소·파일 부재를 확인함 → 직전 전압을 측정하고 탐색 1회만 수집함 → 원본 CSV·JSON과 실제 조건을 전달함 → 무결성 검사와 수치·판정을 대화에서 먼저 보고함 → 별도 결과 문서화 승인 후 결과를 추가함. 확증 n ≥ 3은 유의미한 조건과 목적이 확인된 뒤 별도 계획으로 승인받음.
