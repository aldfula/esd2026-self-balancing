## 1. 실물 사전등재 (실행 전)

- **질문 / 가설**: 기존 편차 검증 r02는 CSV 큐 포화로 중단됐으나 포화 전 기록 스레드의 진행·쓰기 시간이 남지 않아 원인을 좁히지 못함. 선택적 계측을 켠 진단 1회에서 포화가 재발하는지, 재발하면 어느 작업 단계에 머물렀는지와 큐 상태·쓰기 오류가 무엇인지 확인함. 쓰기 작업 중 지연과 다음 작업 시작 전 진행 부재를 구분할 단서를 확보하되 단일 관측으로 SD카드·운영체제 스케줄러를 원인 확정하지 않음.
- **역할 / 비교 범위**: 센서 전용 진단 탐색 n = 1이며 모터·균형 성능 또는 자이로 편차 후보 채택 실험이 아님. 계측 전후 성능 개선을 주장하지 않으며 기존 r02를 대체하거나 편차 확증 n에 포함하지 않음. baseline 성능 비교나 확증 반복은 수행하지 않음. 무재현은 원인 해소·확증 통과가 아님.
- **변경 변수**: 실행 시 `--writer-diagnostics` 하나를 켬. 기본 실행에서는 진단을 켜지 않음. 큐 용량 128·최초 이상 중단·호스트 목표 30 Hz·30초·900샘플·센서 내부 100 Hz·DLPF 5·divider 9·±2 g·±250 deg/s·bus 1·주소 `0x68`을 유지함. 원시값 변환·몸체 축·편차 후보·안전 한계를 변경하지 않음.
- **사전 전달**: 코드·시험·기존 결과 기록·이 사전등재 총 4개 파일을 학생 승인 범위로 commit·origin/main push하고 실제 원격 SHA와 로컬 clean을 확인한 뒤 명령을 전달함. 학생이 Pi에서 clean을 확인하고 fast-forward pull한 뒤 전달한 커밋이 HEAD의 조상인지 확인함. CLI 도움말에 `--writer-diagnostics`가 없거나 코드가 다르면 수집하지 않고 보고함.
- **구동·장착 조건**: 학생이 매 실행 전 배터리→모터 드라이버 입력선 분리 유지·다른 모터 구동 전원 경로 없음·별도 모터 프로그램 미실행을 확인함. Pi·IMU 전원은 유지함. 본체·박스·지지면을 고정하고 바퀴 굴러감을 막으며 실행 중 움직임 없음을 관찰함. 기존 r02 이후의 자세·장착·전원 재연결·재부팅·파일 삭제 여부는 실제 사실로 보고함. 학생 보고와 에이전트 독립 측정을 구별함.
- **전압 조건**: 학생이 이번 수집 직전에 전체 배터리 DC 전압을 새로 측정해 `--vbat`로 입력함. 이전 런의 10.74 V를 재사용하지 않음. CSV·JSON의 반복값은 `manual_pre_run` 사전 수동 측정이며 실시간·셀별 전압이 아님.
- **원본 파일**: `logs/imu-writer-diagnostic-2026-11-24-r01.csv`와 같은 이름의 `.csv.json`을 사용함. 두 경로가 모두 없는지 먼저 확인함. 하나라도 존재하면 삭제·덮어쓰기·이름만 바꾼 재시도를 하지 않고 보고함. 실패·중단 원본도 보존함.
- **최소 계측 내용**: 수집 중 별도 디스크 기록을 추가하지 않고 최근 enqueue 최대 128회의 관측을 메모리에 유지함. 큐 크기·관측 최대치·완료 행 수·기록 작업 단계와 tick·단계 시작 후 경과시간·직전 행 쓰기 시간을 남김. 포화 또는 감지한 기록 스레드 오류의 최초 스냅샷을 종료 처리 전에 별도 보존함. 헤더·행 쓰기·flush의 완료 횟수·최근/최대 경과시간·스레드 CPU 시간과 최대 지연 tick, 쓰기 예외의 종류·메시지·errno를 남김. 종료 후 JSON의 `writer_diagnostics`에 저장함.
- **계측 해석 한계**: 진단 시간은 writer 생성 기준의 단조 시각이고 CSV t는 센서 초기화 이후의 별도 시작점임. 두 값을 같은 시작점으로 뺄셈하지 않음. 큐 크기와 스레드 진행은 동시 관측의 근사값이며 원자적 스냅샷이 아님. 행 쓰기 시간에는 직렬화·버퍼 처리·스레드 실행 지연이 포함되고 물리 SD 쓰기 시간만을 측정하지 않음. 낮은 스레드 CPU 시간과 긴 경과시간만으로 I/O 대기와 스케줄 지연을 확정 분리하지 않음. 버퍼링·flush·fsync 동작을 바꾸지 않으며 디스크 영구 기록 완료를 증명하지 않음.
- **종료 한계**: 기존 큐 종료·join을 유지하므로 기록 스레드가 영구 정지하면 종료 JSON도 완성되지 않을 수 있음. 강제 종료·전원 손실 시 메모리 계측이 유실될 수 있음. 새 timeout·자동 재시작·큐 확대를 추가하지 않음. 이런 경우 재실행하지 않고 현상과 남은 파일을 보고함.
- **단계**: 학생이 코드·구동 조건·고정·원본 파일 부재를 확인함 → 직전 전압을 측정함 → 계측을 켜고 센서 전용 30초 진단 1회만 수집함 → COMPLETE/VOID·실행 명령·전압·실제 움직임·환경 변경과 CSV·JSON을 보존·전달함 → 에이전트가 실제 추가 커밋을 확인하고 양성 대조·무결성·필드·진단 내용을 검사함 → 수치 표·관측·판정을 먼저 보고하고 멈춤 → 결과 문서화는 별도 결과 보고 후 승인을 확인함.
- **로그 무결성 기준**: `python3 -B tools/check_log.py logs/imu-writer-diagnostic-2026-11-24-r01.csv --rate 30 --imu`로 검사함. 분석 전 임시 복사본의 tick 0을 무효화해 검사기가 종료 코드 1로 거부하는지 확인함. 900행·tick 0~899·엄격히 증가하는 시각·최대 Δt < 50 ms·샘플 수와 실제 시간차 × 30 + 1의 차이 1% 이내·모든 샘플 유효·I2C 오류 0·JSON complete·시작/종료 설정 22필드·직전 전압 일치를 확인함. 전체 실행이 중단되면 저장된 앞부분의 정상 간격만으로 유효 런으로 만들지 않음. 원시값 변환 7개 × 실제 저장 행 수, 미측정 빈 셀 6개 × 행 수를 대조함. 종료 설정 부재와 실제 값 불일치를 구별함.
- **진단 기록 기준**: JSON에 `writer_diagnostics`가 있고 큐 용량 128·이력 최대 128회·작업 단계·행 수·시간 요약·오류 정보가 해석 가능해야 함. 무결성과 물리 조건이 충족된 complete라면 「정상 수집·포화 무재현」으로 보고함. 포화 재발 시 런 전체는 VOID로 두되 최초 포화 tick·시각·관측 큐 크기·완료 행 수·worker 단계·진행 tick·경과시간·최대 쓰기 시간과 tick·오류 errno를 표로 보고함. 근거가 부족하면 「원인 미확정」으로 남김. 계측 누락은 「진단 기록 미충족」으로 구별함.
- **중단 기준**: 첫 I2C 오류·새 데이터 부재·주기 위반·설정 불일치·쓰기 실패·큐 포화에서 기존 수집기가 중단함. 흔들림·미끄러짐·굴러감·예상하지 않은 모터 동작은 학생이 즉시 Ctrl+C로 중단하며 모터 동작 시 사람이 구동 전원을 차단함. 완료 출력이 안 나오거나 종료가 멈추면 재실행하지 않고 화면 상태를 보고함. 에이전트가 실물 센서·모터 명령을 실행하지 않음.
